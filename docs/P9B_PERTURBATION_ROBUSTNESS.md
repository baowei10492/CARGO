# P9-B：亚像素与旋转扰动（预注册协议）

> 预注册时间：2026-07-26，运行之前  
> 定位：加固队列第二项。审稿人必问"你们的注入全是整数像素平移，
> 亚像素呢？旋转呢？"——本节既是加固，也是**能力边界的诚实刻画**。

## 1. 被测的是"优雅降级"，不是"能不能修"

两类扰动都**在方法的表达能力之外**，这是结构性的、事先已知的：

```text
亚像素平移 0.5 / 1.0 / 3.0 px
  定位器把 offset 解码到 2 px 描述子栅格上，前两档低于其可表示分辨率
旋转 0.25 / 0.5 / 1.0 度（1024 px 下角点位移约 3.2 / 6.3 / 12.6 px，
  正好覆盖 2/4/8 px 平移的量级）
  **任何单一平移都无法纠正旋转**，故旋转直接违反已确立的适用域条件
  "残余失配须近似为全局平移"
```

因此本节要检验的**不是**"能否纠正"（结构上不能），而是：
**风险受控路由能否识别出自己帮不上忙，从而不造成净损害。**
这正是本文安全性主张在域外扰动上的直接检验。

## 2. 判据（预注册）

```text
主判据（无损害门）：primary = safe_veto_task
  对每个扰动场景：F1(primary) >= F1(raw) − 0.005
  clean 亦须满足同一条
  全部满足 → router_degrades_gracefully_outside_scope
  任一不满足 → router_does_net_harm_documented_limitation
容差 0.005 是 P7-3 clean 预算（0.001）的五倍，因为这些扰动把工作点
  推得比 clean 远得多；该值在运行前写定，**事后不得放宽**
```

**失败是被允许的结局**：它不与适用域条件矛盾，而是把它变得更锐利
（"近似全局平移"里的"平移"二字获得实证边界）。届时如实记为限制。

## 3. 对经典基线的公平性处理

相位相关默认取相关峰的整数 argmax。本节为它加上**抛物线亚像素细化**
（三点拟合，退化时返回 0 不臆造位移）：

```text
不加细化，就是在经典方法结构上占优的那条轴上给它设障——
本文定位器受 2 px 栅格限制，而相位相关天生可亚像素。
实测：真值 0.5 px → 整数峰 1.00，细化后 0.504；1.5 px → 2.00 / 1.501
```

**允许经典方法在亚像素档反超**，这是预期之内的结局，必须如实报告。

## 4. 实现要点（均有测试）

```text
亚像素平移用 affine_grid + bilinear；整数量值必须与原整数切片路径
  在内部区域逐点一致（<1e-4）——否则每个亚像素数字都暗含插值惩罚。
  首版用了 align_corners=True 的归一化 (2dx/(W−1)) 而采样用
  align_corners=False，误差 0.076；已修为 2dx/W。
方向向量取**单位长度**：severity 是模长，若沿用整数版的对角方向
  （长度 √2）会把 0.5 px 悄悄放大成 0.707 px。
旋转**不写 shift_dx/shift_dy**（保持 0），角度另存
  rotation_degrees——防止任何工具把旋转当平移去打分（F7 家族预防）。
边界有效掩膜由 grid_sample 的支撑集导出，与整数路径口径一致。
```
