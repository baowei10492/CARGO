## 0. 为什么需要新协议

```text
事实一（§71.3, §71.5 F8）：像素定义的位移跨 GSD 不可比。
  LEVIR 0.5 m 下 2/4/8 px = 1/2/4 m；WHU 0.075 m 下同样 2/4/8 px 只有 0.15/0.3/0.6 m。
  WHU「需要」的证据（S8 headroom 0.1088）是在这种温和 6.7 倍的扰动下测得的。
事实二（§73, §121）：原分辨率下定位不可行。
  WHU 原生训练的定位器连训练集上 S4 都只有 PCK@1 0.13；
  原分辨率加大窗口到 3072 px 也只有 0.417。WHU 在原分辨率上带有多像素、
  非全局的固有失配（跨航次视差是相容但未单独证实的机制）。
事实三（§77, §79）：粗 GSD 下同一冻结定位器零适配即完美。
  3072 px 窗口降到 512（0.45 m）时 S4 PCK@1 = 1.000，但当时注入的是
  降采样图上的 2/4/8 px，即原图 12/24/48 px。
推论：「原图小位移 + 粗尺度估计」不改变注入位移与固有失配的比例，却要求
  1/6 粗像素的精度，旧证据一致指向不可行（方案 A）；
  「按物理量对齐 LEVIR 的位移 + 粗尺度估计 + 原分辨率检测」有直接可行性证据（方案 B）。
```

## 1. 设计

```text
位移族 B（主）：原图 12 / 24 / 48 px = 0.9 / 1.8 / 3.6 m
  方向：与 P8 同一种子规则（_stable_seed(3407, tile_id, "shift", severity)），
        即同一瓦片、同一严重度下 A 与 B 方向相同，只差 6 倍幅值，逐瓦片配对
  为何不用 13/27/53：6 的倍数经 6 倍 BOX 降采样后恰为整数 2/4/8 px
        （降采样与平移严格可交换，测试钉住），且落在定位器 ±8 px 搜索域内；
        物理量为 LEVIR 1/2/4 m 的 0.9 倍，与 §77 的 0.45 m 探针点一致
位移族 A（对照）：原图 2 / 4 / 8 px，与 P8 Gate 1 完全相同
窗口：3072 px（230.4 m）以瓦片为中心；贴栅格边时整体平移而非填充。
  val 瓦片的窗口可包含 train/缓冲列的影像——只用于估计位移，不读其标签
注入：在整个窗口上对 T2 做整数平移（反射填充只发生在窗口边缘），再裁出瓦片，
  因此瓦片内部是真实上下文，而非 P8 瓦片级注入的反射内容
定位：窗口 6 倍 BOX 降采样到 512（0.45 m）→ 冻结 LEVIR P7C
  （sha256 389c65e1…325b2，零适配、不训练、不改半径、hard 解码 + threshold_nonzero 门）
  → 条件偏移 × 6 → 原分辨率双线性 warp
检测：冻结 P8 WHU DINOv3 部分微调检测器，原分辨率 512 瓦片，fp32（与 P8 评估一致）
打分：P22 主测量的全部场景 × 全部路径使用**同一个** 48 px 内边界支撑
  （416×416 = 173,056 px/瓦片，174 瓦片共 30,111,744 px；工具核验各场景像素数相等，
  不等即中止）。48 = 最大注入位移，因此没有任何反射或边界丢失像素被计分，
  且伤害、天花板、恢复率都是同一批像素上的差值（P12「same valid pixels」纪律）。
  锚点例外：按 P8 原口径复现（见 3.1）
```

### 1.1 搜索域边界与钳制注解

冻结定位器的搜索域为 ±8 粗像素（search_radius 4 × 描述子步长 2，由检查点推得，
不手写）。B 族 severity 3 = 8 粗像素，恰在域边界上——与 LEVIR 主线的 8 px 同一约定，
但主记录 §73.2 指出：真值落在边界时，被钳到边界的估计会与真值偶然重合（伪命中）。
处理：每个场景报告 est / gt 边界率及其差（§75.2 修正后的注解），钳制只会**抬高**
severity 3 的 PCK，不会压低，因此 **severity 2（4 粗像素，域内）是有约束力的判据**，
severity 3 仍须同时通过。

## 3. Gate 1（val 174 瓦片；读标签；仅在 Gate 0 通过后）

### 3.1 锚点（主记录 §85：新管线先复现已知数值）

```text
用瓦片级反射注入（P8 原口径）复现 P8 Gate 1，容差 1e-4；参考值取自
reports/p8_whu_p3b/20260726T145440Z/{raw_val,oracle_val}/results.csv：
  clean 0.93445407
  raw（单侧支撑，P8 原口径）S1 0.91631449 / S2 0.88565873 / S8 0.82526188
  oracle（配对支撑）S1 0.93450297 / S2 0.93456561 / S8 0.93405923
勘误（2026-09-14，主测量运行之前）：首版参考值抄自主记录 §71.1 表格，该表 raw 与 oracle
  两行有笔误（headroom 行正确），导致首次锚点误判 anchor_failed。实际观测与上面的
  权威值逐位一致（8 位小数），有效像素数也逐一吻合（raw 单侧、oracle 配对）。
  此处只更正抄录，容差未动；详见主记录 §155。
不通过 → anchor_failed，主测量不运行，先查实现。
批大小从 P8 协议文件读取（与 evaluate_robustness 同一解析顺序），使 cuDNN 算法选择
  与 P8 一致；输入逐字节相同（同一 _load_raster、同一裁块原点、同一归一化、同一
  注入函数），预期逐位复现。
事前写定的数值噪声处理：若锚点失败但全部 |delta| < 1e-3，且偏移/支撑诊断无异常，
  记为数值差异（TF32 / 算法选择），把观测到的 delta 写入记录并把容差改为观测值的
  2 倍后继续；|delta| >= 1e-3 一律视为实现错误，停下诊断。
附带发现（写协议时查到）：P8 的 raw 运行未加 --paired-shift-support，
  而 oracle 在配对支撑上打分，§71.1 的 headroom 0.1088 是混合口径。
  锚点另报 raw 在配对支撑上的值（raw_paired，不参与比对），给出 P8 若配对应得的数；
  不改历史判定，差异如实记录。
```

### 3.2 主测量

```text
每瓦片 × 7 场景 × 4 路径：
  raw              平移后 T2 直接检测
  oracle           已知位移精确逆平移（天花板，定位器无关）
  estimated        用估计偏移校正（无条件）
  estimated_gated  仅当 q 门触发才校正，否则同 raw
判据（只作用于 B 族）：
  (a) 需要：raw clean − raw B-S3 >= 0.05
  (b) 天花板：oracle − raw（B-S3）>= 0.05
  (c) 可恢复：(estimated − raw) / (oracle − raw) >= 0.50，在 B-S2 与 B-S3 同时成立
  依次判定：anchor_failed / no_step_needed / headroom_insufficient /
            recovery_insufficient / proceed_to_gate2
描述量（不作判据）：estimated 与 estimated_gated 的 clean F1（无条件校正对 clean 的伤害、
  门控误触发的伤害）；val 上的定位误差、q 触发率与边界注解；A 族全部路径
A 族在本关测的是「粗尺度仪器施加于原图小位移」：硬偏移网格为 12 原像素，
  2/4/8 px 只能被量化为 0 或 12，因此 A 族 estimated 预期有害。它证明的是
  「同一仪器在原图像素协议下不可用」，不是「原分辨率定位器的最好成绩」——
  后者已由 §73（原生训练 PCK@1 0.13）与 §121（原生大窗 0.417）给出。
```
