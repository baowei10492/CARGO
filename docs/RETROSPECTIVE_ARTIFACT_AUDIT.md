## 1. 需要更正表述的一处：P5c 的"S2Looking 泛化失败"

### 1.1 问题

P5c 在 S2Looking 上的正式判定是 FAIL，依据是绝对门槛
（Shift-8 gain >= 0.050 等）。但主记录 45.2 后来实测出 S2Looking 的
输入级 Oracle headroom 仅 S2 +0.004 / S4 +0.013 / S8 +0.033——**该
绝对门槛在这个数据集上物理不可达**，任何方法都会失败。更进一步，
卫生诊断 v2（主记录 67）已证实 S2Looking 属空间变化场，**本就在
方法适用域之外**。

因此"P5c 在 S2Looking 上泛化失败"这句话，测的主要是数据集属性，
不构成对 P5c 的有效否证。这属于 F4 的近亲：判据与被测对象不匹配。

### 1.2 方向是否被误判：没有

P5c 降级的另一条依据是纯机制性的、与门槛无关：主记录 45.2 测得
**深特征对齐相对输入级对齐存在近似恒定的后编码残差**
（LEVIR 0.0116/0.0127/0.0155，S2Looking 0.0038/0.0050/0.0053），
来自 ConvNeXt 下采样与插值的平移非等变性，改 Warp 消不掉。这条独立
支撑"对齐要放到 backbone 之前"，而 P7 路线正是由它驱动。

且在 LEVIR 单数据集上，输入级明显更强：

```text
P5c 三种子 Shift-8 gain = +0.0786 ± 0.0097
P7-3 veto-reg 三种子 Shift-8 gain = +0.1583 ± 0.0123（约 2 倍）
```

结论：**方向（特征级 → 输入级）成立，依据应改为 LEVIR 侧的机制残差
与增益差，而不是 S2Looking 的绝对门槛失败。**论文中 P5c 的降级理由
必须按此表述，否则等于用一个域外负例否证一个方法。

## 2. 污染但使判定更稳的一处：Stage C 的 PCK@1 = 0.486

Stage C 无标签门用 LEVIR 定位器（radius 4）在 S2Looking 上测得
Shift-8 conditional PCK@1 = 0.486 < 0.50，判定停止。

C2b-R 后来证明：在 S2Looking 上，radius 4 的 PCK 被**钳制伪命中**
系统性高估（同一数据从 0.632 掉到 radius 6 的 0.316）。因此 0.486
这个数字**本身偏高**，真实任务坐标精度更差。

方向：判定为"停止"，而真值更差 → 判定更稳固，无需更正。这是 F1
朝有利方向偏的一例，但仍应在论文中注明该数字含钳制成分。

## 3. 复核后基本成立、但留有脆弱性：禁令 #8（不扩大 search radius）

### 3.1 复核

禁令来自 P7-1 的 search-support 诊断（LEVIR）：扩大搜索范围后
PCK 0.594 → 0.641 却仍低于 raw_current 0.750，结论是"问题来自
zero candidate 竞争，而非 radius 不够"。

是否也是钳制伪命中？**不是**。关键区别：

```text
S2Looking：光度真值 = 注入 + 固有 ≈ 10–11 px，在 ±8 域外
  → 钳到边界恰好等于任务答案 → 伪命中
LEVIR：固有场 ≈ 0，光度真值 ≈ 注入；即使 Shift-8 对角情形
  真值 (8,8) 的模长 11.31，但两个分量各为 8，**是 radius 4 栅格
  上的合法候选，可达** → 不构成伪命中
```

扩域在 LEVIR 上把候选数从 80 增到 168，多出 88 个干扰候选，PCK
下降是合理的机制解释。故禁令的 LEVIR 依据成立，S2Looking 的一次性
豁免（主记录 61.4）也因失败模式不同而正确。

### 3.2 遗留脆弱性（应入论文）

主记录 69.3：LEVIR Shift-8 约半数注入为对角，真值 (8,8) **恰在
±8 搜索域角点、零余量**。任何亚像素残差或轻微固有失配都会把真峰
推出域外。这是评测协议本身的脆弱性，不是方法缺陷，但必须报告。

### 3.3 未完全核实项

P7-1 的四个数字（final 0.594 / raw_current 0.750 / best_nonzero
0.797 / expanded 0.641）各自的精确定义未在本次复核中回溯到原始
服务器报告。若将来考虑在 LEVIR 上重启 radius，**必须先回读该报告
确认这四个量的口径**，不能凭记录里的摘要行事。

## 4. 贯穿多处的系统性脆弱：LEVIR val n = 64（F6）

LEVIR validation 只有 64 张图，1 张 = 1.5625 个百分点。P7-1x 系列
的多个估计器判断依赖很小的图像数差：

```text
P7-1C：clean PCK 96.88% → 93.75%  = 2 张图
P7-1B：Shift-8 51.56% → 92.19%    = 26 张图（结论稳）
P7-1C：Shift-8 51.56% → 75.00%    = 15 张图（结论稳）
边界 OR：clean 96.88% → 65.63%    = 20 张图（结论稳）
```

n=64、p≈0.75 时二项比例的 95% 区间约 ±10.6 个百分点。因此：

```text
凡 PCK 差异小于约 5 个百分点（3 张图）的历史陈述，
都应视为噪声内，不得作为结论依据。
```

复核结果：**主要方向性判定都依赖 15–26 张图的大差异，不受影响**；
受影响的是"clean 略降 2 张"这类描述性语句。论文报告 PCK 时必须给
置信区间或图像数，不得只报百分比。

注：F1 类指标（分割 F1）按像素池化，样本量是 6.7×10^7 像素级，
不受此限；本节只针对逐图 PCK/选择率类指标。

## 5. 从未审计过的潜在问题：LEVIR 官方划分的空间泄漏（F3 同族）

### 5.1 问题

WHU 暴露的 `parent_id_coverage = 0.000` 空洞零，**同样适用于 LEVIR
与 S2Looking 的历史审计**：两者的 manifest 都用默认
`--parent-id-mode none` 构建，因此各自审计报告里的
`cross_split_parent_ids = 0` 都是空洞的——跨划分 parent 泄漏检查
从未运行过。

这在 LEVIR 上尤其值得追查：LEVIR-CD 的 1024×1024 patch 是从约 20 个
更大区域切出的，官方 train/val/test 划分是否**区域不相交**，本项目
从未验证；文件名（train_1.png 等）不含区域信息，无法从命名判断。

### 5.2 影响评估

若 LEVIR 官方划分在区域上有重叠，则 val/test 与 train 空间相关，
**绝对 F1 会被系统性高估**。但：

```text
本项目全部预声明门槛都是"同一 val 上不同方法的相对比较"
（raw / q gate / veto / oracle），空间相关性对各分支同等作用，
相对增益与 Oracle recovery 不受影响 → 方法结论不变。
受影响的是绝对数值的外部可比性（如 clean F1 0.9032 与文献对比）。
```

### 5.3 应补的检查（廉价）

```text
对 LEVIR train/val/test 做跨划分近重复检测：
  下采样到 64x64 灰度 → 计算 pHash 或直接 L2 → 找跨划分最近邻
  若出现大量高相似对 → 官方划分存在区域重叠，需在论文中声明
  纯 CPU、分钟级、不消耗任何评估机会
```

WHU 侧本项目已用列条带 + 缓冲带自行保证不相交，并已把 parent_id
置为列号使该检查真正运行——这是三个数据集里唯一有显式空间不相交
保证的一个，应在论文中说明这一差异。

## 7. 结论与待办

### 7.1 结论

```text
没有一处方向性误判。
需要更正表述的：P5c 的降级理由（第 1 节）。
需要在论文中注明的：Stage C 的 0.486 含钳制成分（第 2 节）；
```

### 7.2 待办（按成本排序）

```text
1. LEVIR/S2Looking 跨划分近重复检测（CPU、分钟级）→ 第 5.3 节
2. 给 LEVIR 与 S2Looking 的 manifest 补 parent_id 并重跑审计
   （若能构造出可信的 parent；LEVIR 无区域信息，可能只能靠
    第 1 项的近重复结果反推分组）
3. 论文写作时按 7.1 逐条落实表述更正
4. 若将来考虑在 LEVIR 上重启 radius：先回读 P7-1 原始报告核实
   四个 search-support 量的口径（第 3.3 节）
```

### 7.3 元结论

四类陷阱有一个共同结构：**指标的可信度取决于测量装置与被测对象的
匹配程度**，而不取决于数字本身好不好看。已识别的六种表现形式
（F1–F6）建议在论文的实验方法一节单独成段——它们不是本项目的瑕疵
清单，而是"配准类工作如何不骗自己"的可复用检查表，其中钳制伪命中
与强制选择混淆两条有本项目的前后对照实证。

## 8. 审计写成后当天新增的两个实例（F 家族扩充）

**F7 检查运行了但键的口径错 → 假警报。** parent_id 修复后，审计报出
22 个跨划分共享 parent（`passed: False`），但那是因为 parent_id 只键在
列号上，而 train 列与 test 列出自两幅不同栅格——同号列被误判为同一
parent。真正的不变量（train 与 val 列不相交）其实通过。已改为复合键
`raster_split|column`。教训：**零不可信，非零也不自动可信**；键的
口径必须与被验证的不变量精确对应（主记录 70.7 第 1 条）。

**F4 的强化实例：阈值不可迁移。** 卫生诊断 v2 的门槛
（D<=2 绿 / >=4 红）在 1024/512 配置下校准。改到 512/256 后，
**LEVIR 自身 S8 的 D 从 0.000 变成 7.606**，参考数据集自己判红。
因此阈值随仪器配置失效，不能跨配置搬用。这比"跨数据集不可比"更进
一步：**同一数据集换测量配置，阈值即失效**。免阈值的相对排序
（tile_error_pck4 在每个场景上 LEVIR > S2Looking > WHU）仍然可用
（主记录 70.7 第 3 条）。

对第 7.3 节元结论的补充：可复用检查表由六条扩到七条，且应加一句总纲
——**任何阈值都必须与它被校准时的测量配置一起报告**，脱离配置的阈值
没有意义。
