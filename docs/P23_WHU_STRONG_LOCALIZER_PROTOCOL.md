## 0. 缘由（来自 P22 的结果，按 P22 §156.2 第 4 条注明）

```text
P22 Gate 1（主记录 §156）：物理位移 B 族 3.6 m 使 WHU F1 0.936 → 0.400，oracle 全部追回；
  冻结 LEVIR 定位器 P7C 的估计校正只追回 42.9% / 50.0%（B-S2 / B-S3），判 recovery_insufficient
同一 P7C：train 区（Gate 0）B 族 180/180 精确、clean 0/60 误触发；
  val 条带 B 族误差 5–16 px、clean 误触发 33%，失效与窗口变化占比强相关（§157，Spearman 0.87–0.98）
问题：val 条带的失败是「P7C 这个定位器不够强」，还是「数据本身不可解」（区域性视差等）？
  换用已发表的强定位器是最直接的区分：若强定位器在同一窗口上能跟住位移，失败归定位器；
  若所有候选都失败或都在 clean 上报出同一个非零偏移，指向数据本身
```

## 1. 设计：只换定位器，其余全部继承 P22

```text
继承（工具核对 P22 配置 sha256，不同即中止）：
  栅格与 val 条带（列 35–40 × 行 0–28，174 瓦片）、3072 px 窗口、7 个场景
  （clean、A 族 2/4/8 px、B 族 12/24/48 px = 0.9/1.8/3.6 m）、种子与方向规则、
  冻结 P8 WHU DINOv3 检测器、48 px 共用内边界支撑、Gate 1 判据数值
定位器（跑前冻结，统一接口：输入同一对 3072 px 窗口，输出原图像素平移 (dx, dy)，
  约定 reference(x, y) ↔ target(x + dx, y + dy)）：
  p7c               参照：6 倍 BOX 降采样 → 冻结 P7C → × 6，自带 q 门（与 P22 逐位相同）
  roma_outdoor      唯一候选：RoMa 稠密匹配（CVPR 2024；romatch，outdoor 权重 + DINOv2 ViT-L），
                    3 倍降采样（1024 px），按置信度采样 5000 对匹配，每对样本的采样种子固定
为什么是 RoMa：通用稠密匹配中精度最高的公开方法之一；大量匹配加一致性估计，对变化区域天然稳健；
  DiffRegCD 的配准分支也以 RoMa 为基础，便于论文中对照「同类配准能力下的强制对齐 vs 选择性对齐」
公共设置：
  搜索先验 ±96 原像素（最大注入 48 px 的 2 倍；P7C 保持其结构性 ±48 px）
  平移一致性：确定性穷举 RANSAC（每个匹配都是假设，内点最多者胜，取内点均值），
    阈值 1.0 工作像素，最少 8 个匹配；不足即记未收敛、偏移为 0
  零位移判定（RoMa）：|偏移| > 6 原像素才算「有错位」（= P7C 1 个粗像素，
    即 P22 Gate 0 的 clean 容差）；P7C 用自己的 q 门
  校正时偏移取最近整数像素（整数平移在双线性采样下精确，clean 上 0.3 px 的估计不会模糊图像）
依赖与权重：romatch（及其依赖 kornia 等）与 fused-local-corr 0.1.1 由用户在服务器安装（均 --no-deps，torch 保持 2.5.1）；
  RoMa 与 DINOv2 权重由用户放入 torch hub 缓存；
  运行时把 torch hub 缓存中全部权重文件的 sha256 与库版本写入 weights_manifest.json
```

## 2. 筛查（无标签；train 区 60 块 + val 条带 174 瓦片）

### 2.1 自检（先于一切）

```text
RoMa 取前 3 个 train 块，把 T1 窗口与「自身平移 (24, −24)、(−48, 12)、(0, 0)」配对，
  估计误差须 <= 1.5 原像素且全部收敛。检验符号、单位与缩放；失败 → selfcheck_failed，停止
P7C 不做自检：它不能输出零偏移（强制选择底噪），其正确性由 2.2 的锚点逐行核验
```

### 2.2 P7C 锚点（主记录 §85、§155 的教训：直接读权威文件）

```text
P7C 在本工具中的每一行必须复现 P22 的两个偏移文件：
  train 块 ↔ reports/p22_whu/gate0/<LATEST>/run/gate0_offsets.csv（420 行）
  val 瓦片 ↔ reports/p22_whu/gate1/<LATEST>/run/gate1_offsets.csv（1218 行）
逐 (id, scenario) 比较：条件偏移差 <= 1e-4 且 q 门完全一致，参考行一行不缺
不通过 → anchor_failed，RoMa 不运行
```

### 2.3 主测量与判据

```text
P7C 与 RoMa × 每个窗口 × 7 场景：估计、是否触发、是否收敛、耗时
判据（只看 val 条带的 B 族，原像素 PCK@2 = 误差 <= 2 px 的比例）：
  tracks：B-S1、B-S2、B-S3 的 PCK@2 均 >= 0.80
  clean_passed：clean 触发率 <= 0.10 —— 报告，不单独止损（P22 先例）
结论（参照 P7C 不参选；工具中的通用选择规则在唯一候选下退化为「RoMa tracks 即选中」）：
  RoMa tracks → verdict = proceed_to_gate1，selected = roma_outdoor
  RoMa 不 tracks → stop_no_candidate_tracks：P23 止于此，
    WHU 线的下一步只能是自研定位器或另一现成匹配器（均须另立协议），或按边界写入论文
为什么是 PCK@2：P22 A 族显示原图 2 px 残差约损失 1.8 pp、4 px 约 4.8 pp，
  相对 B-S3 天花板 53.7 pp，2 px 以内的残差几乎不影响恢复
```

### 2.4 描述量（不作判据）

```text
train 区两者的同一组量（应接近完美；与 val 对照，看区域差是否仍存在）
val 条带按窗口变化占比分箱（0–5%、5–10%、10–15%、>=15%）：B-S3 PCK@2、clean 触发率
  —— 检验强定位器是否消除了 §157 的「变化越密越失效」
clean 一致性：同一 clean 瓦片上 P7C（q 门触发）与 tracks 的 RoMa 同时判为有错位、
  且偏移相差 <= 3 px 的数量与偏移（RoMa 不 tracks 时不计）
  —— 两种原理完全不同的定位器在 clean 上报出同一非零偏移，是数据本身存在残余错位（如视差）的证据；
  P7C 在 val 条带上不可靠，故只作提示性证据
A 族（原图 2/4/8 px）全部量：原分辨率精度的对照
标签使用：只为「变化占比」一列读取 val 窗口标签（P22 Gate 1 已读过），判据与选择不用任何标签
```

## 3. Gate 1（读 val 标签；只对筛查选出的一个候选；仅在筛查通过后）

```text
每瓦片 × 7 场景 × 6 路径：
  raw / oracle / p7c_estimated / p7c_gated —— P22 Gate 1 的原计算，同批大小、同顺序
  estimated        用选中候选的估计（取整）无条件校正
  estimated_gated  仅当选中候选判定「有错位」才校正，否则同 raw
锚点：前四条路径的 F1 必须复现 P22 Gate 1 的表（reports/p22_whu/gate1/<LATEST>/gate1_decision.json），
  7 场景 × 4 路径全部 |差| <= 1e-4；不通过 → anchor_failed，选中候选的数字不报告
判据：与 P22 完全相同，作用于选中候选的 estimated（依次）：
  no_step_needed（raw clean − raw B-S3 < 0.05）/ headroom_insufficient（B-S3 oracle − raw < 0.05）/
  recovery_insufficient（B-S2 或 B-S3 恢复率 < 0.50）/ proceed_to_gate2
描述量：estimated 与 estimated_gated 在 clean 上相对 raw 的变化（P7C 为 −17.3 / −13.4 pp）；
  B-S1 恢复率；选中候选在 val 上的定位量
val 再次使用的披露：P22 Gate 1 已读过这批 val 标签；本次只读一次，只评估无标签选出的一个候选，
  不在候选之间按 F1 挑选。论文中如实写明「定位器由无标签筛查选出，val 第二次使用」
```

## 4. Gate 2 及以后（仅在 Gate 1 通过后）

```text
  B-S3 oracle 恢复率 >= 0.50
选择器（窗口感知的路由特征、train 特征采集、阈值标定）须另写实现说明并落盘后才运行，
  且须先复现本协议 Gate 1 的 raw / oracle 数值
```


## 6. 报告口径

```text
每个数字同时给出像素与米；结论只能表述为「在物理量与 LEVIR 可比的位移下」
筛查通过只说明「该定位器在 WHU val 条带上能跟住注入位移」，不等于方法有效；
  方法有效须 Gate 1、Gate 2 与一次性 test 依次成立
若 RoMa 失败，结论只能是「RoMa 在该区域不可用」，不得外推为「所有现成定位器均不可用」；
  并结合 clean 一致性讨论数据本身
```

## 7. 事前预期（写于运行前，不作判据）

```text
train 区：两者大概率接近完美（P7C 已是 180/180）
val 条带：RoMa 以大量匹配加一致性估计，对变化区域天然稳健，大概率 tracks
最大不确定性：若 val 中段存在真实区域性错位（P7C 的 clean 误触发多为 (0, −12) 或 (12, −12)），
```
